## Notes

### Leaks

Every leak is the same in both builds, in count, bytes and allocating
function.  So all of them are inherited from INN 2.8.0; the conversion added
none.

| Program | Leaks | Allocated in (baseline / alpha3) | Kind |
|---|---|---|---|
| innfeed | 3 | `mainOptionsProcess`, main.c:854, 886, 901 / main.cc:860, 892, 907 | option strings, once at startup |
| innfeed | 1 | `newHostParams`, host.c:475 / host.cc:475 | default host parameters, once per configuration read |
| nnrpd, each session | 46 | no stacks: stack logging turns itself off in nnrpd's forked session processes | per session process |
| expireover | 1 | `ReadInDescriptor`, readin.c:67 / readin.cc:67 | 2 KB buffer, once per run |
| makehistory | 4 | `concat` (2 stacks) | path strings, once per run |

**Growth over time.**  None of these grow with the amount of work:
- The 2,000-article and 40,000-article runs report the same counts and
  bytes.
- The innfeed, expireover and makehistory leaks happen once per process.
  expireover and makehistory exit when they finish.
- The nnrpd leak stays in the session's own process, which exits when the
  reader disconnects.
- The long-running nnrpd daemon and innd report no leaks.

One growth path is not measured: if `newHostParams` leaks again each time
innfeed re-reads `innfeed.conf`, a long-running innfeed that is reloaded
often grows by about 192 bytes per reload.  The workload does no reloads.

### Method

- **The timing pass** was rerun three times before a clean run:
  - The first rerun had an extra baseline repetition, caused by a script
    edit made while the script was running.
  - The second was blocked by a leftover innd that held the port.
  - The run reported here started on an idle machine with no leftover
    processes.  It has 5 repetitions per build and no failures.
- **The leak pass:** the first alpha3 attempt failed W4's single-session
  check.  It ran while the coverage builds were compiling, and under that
  load the client session took longer than the script's 60-second wait.
  - The script now waits up to 300 seconds and records the client's errors.
  - The alpha3 rerun passed.  It is the alpha3 column above.
  - This was a fault in the test harness, not in nnrpd, so it is not marked
    FAILED.
- **Coverage** leaves out innfeed's generated parser (`config_l`,
  `config_y`, from lex and yacc):
  - The baseline generates these files in the source tree; INN++
    generates them in the build tree.
  - They are not hand-written code.
- **Lines of code** were counted with cloc: code lines only, without tests.
  - `total(no-tests)` counts every language, including shell, Perl, CMake
    and documentation markup.
  - `total-C/C++(no-tests)` counts the compiled code only.
- **The libraries grew** (libinn by 37%, libinnstorage by 21%), mostly
  from C++ standard-library code: templates and exception tables.
  - The programs grew by between 4% and 14%.
  - The programs' memory use did not grow.  innd's peak footprint is 10%
    lower.

### Architect's summary

Some minor gains in memory use can already be seen in innd: its peak memory
footprint is 10% lower.  The leaks match up, as expected for a minimal
change effort in moving from C to C++.
